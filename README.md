# Hospital RAG Platform

A Retrieval-Augmented Generation platform for hospital use. It produces
**grounded answers with verifiable citations** over clinical guideline
documents, adds **non-directive** structured inference from patient records
(synthetic only), and wraps both in a **multi-agent orchestration layer** with
persistent memory, human-in-the-loop (HITL) escalation, and a multi-rater
evaluation workflow.

> **This system does not generate diagnoses, treatment plans, or independent
> clinical recommendations.** It reports and cites retrieved source material.
> Every response carries a non-removable disclaimer. See
> [CDS-FUTURE.md](CDS-FUTURE.md) for the capabilities that are deliberately
> excluded.

> **No real PHI, ever.** All development, test, and demo data is synthetic and
> generated by this project.

        ┌──────────────────────┼───────────────────────┐
        ▼                      ▼                       ▼

 (ingestion, long        orchestrator            (system of record:
  agent runs, eval)      (9 agent roles)          corpus, records, memory,

## Tech stack

- **Backend:** Python 3.11+, FastAPI, SQLAlchemy 2.0, Pydantic v2, Alembic
- **Orchestration:** LangGraph (Postgres checkpointer)
- **Async:** Redis + Celery
- **Vector store:** Qdrant (dense + sparse, server-side RRF)
- **Relational:** PostgreSQL (schemas: `corpus`, `records`, `memory`, `hitl`,
  `eval`, `audit`, `iam`)
- **LLM:** self-hosted gateway via `LLMGateway`; model id from config; offline
  deterministic `stub` for dev/CI
- **Frontend:** React (Vite + TypeScript), served static behind nginx
- **Deploy:** docker-compose (single host, no external network needed for core
  flows)

## Requirements

- Docker + Docker Compose
- (Local dev without Docker) Python 3.11+, Node 20+, and a running
  PostgreSQL 16, Redis 7, and Qdrant
- Optional GPU for embeddings/reranking; a CPU fallback is supported but slower
  (documented per-model). Reference dev machine: modern multi-core CPU, 32 GB
  RAM, optional NVIDIA GPU.

## Setup

```bash
cp .env.example .env
# edit .env — at minimum set MODEL_ID (the answer path refuses to start on the
# placeholder) or use EMBEDDING_BACKEND=stub / the llm-gateway stub for offline dev
```

### With Docker (recommended)

```bash
make up            # docker compose --profile dev up -d  (api, worker, redis,
                   # postgres, qdrant, proxy, frontend, llm-gateway stub)
make migrate       # alembic upgrade head
make seed          # create schemas/roles + seed rubric domains + demo users
make gen-data      # generate synthetic patient records into data/synthetic_records/
make fetch-guidelines   # fetch / generate sample guideline docs into data/sample_guidelines/
```

App: `https://localhost/` (self-signed dev cert). API docs: `https://localhost/api/docs`.

### Without Docker

```bash
cd backend
python -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"
alembic upgrade head
python -m scripts.seed_db
uvicorn app.main:app --reload
# separate shell:
celery -A app.worker.celery_app worker -l info
# frontend:
cd ../frontend && npm install && npm run dev
```

## Configuration

All config is via environment variables / `.env` (secrets via
`SECRETS_BACKEND`). Full list and defaults: [ARCHITECTURE.md](ARCHITECTURE.md)
§20 and [.env.example](.env.example). Key ones:

| Var | Default | Notes |
|---|---|---|
| `MODEL_ID` | `<set-me>` | primary LLM id; **answer path refuses to start on the placeholder** |
| `MODEL_ID_FALLBACKS` | `` | comma-separated fallback model ids |
| `MODEL_ID_VERIFIED` | `false` | set `true` only after checking the id against current gateway docs; `false` logs a startup warning |
| `LLM_GATEWAY_URL` | `http://llm-gateway:8080` | self-hosted gateway |
| `EMBEDDING_MODEL_ID` | `BAAI/bge-large-en-v1.5` | **UNVERIFIED placeholder** — confirm/override |
| `RERANKER_MODEL_ID` | `BAAI/bge-reranker-v2-m3` | **UNVERIFIED placeholder** — confirm/override |
| `EMBEDDING_BACKEND` | `local` | `local` \| `gateway` \| `stub` |
| `SECRETS_BACKEND` | `file` | `env` \| `file` \| `vault` |
| `AUTH_PROVIDER` | `devjwt` | `devjwt` \| `oidc` |
| `PATIENT_RECORD_VECTORS_ENABLED` | `false` | keep off unless deliberately enabling record vectorization |
| `LOCAL_ADAPTATION_ENABLED` | `false` | inert extension-seam flag; see CDS-FUTURE.md |

## Security & compliance posture (summary)

- Every patient-record field is PHI by default; encryption in transit (TLS at
  the proxy) and at rest (host volume encryption + application-level envelope
  encryption for PHI free-text/blob fields).
- RBAC (roles: clinician, reviewer, admin, service) at the API layer plus
  row-/field-level controls at the data layer; `purpose`-of-use required on
  every patient-scoped call.
- Immutable, append-only audit log (`audit.audit_event`) with a hash chain;
  one event per query / retrieval / record access / answer / HITL action /
  ingest / config change / login.
- PHI never leaves the deployment; model calls go only to the self-hosted
  gateway; logs are PHI-redacted; no training on PHI.

Full model: [ARCHITECTURE.md](ARCHITECTURE.md) §17–§18.
